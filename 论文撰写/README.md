# MCM/ICM 美赛论文写作完整指南

> 基于 2016-2024 年 O 奖论文分析。本指南整合并修正了此前各专题文件中的冲突与错误，面向大一新生，也适用于有参赛经验的选手查漏补缺。
>
> **样本说明**：不同分析板块基于不同样本量——总体结构分析覆盖约 300 篇论文，近五年深度分析约 90 篇，逐句文本细读约 14 篇。各板块会在需要时注明样本来源，不再笼统声称"基于 X 篇论文"。

# 第一部分：核心认知与写作哲学

## 1.1 MCM vs ICM：首先了解你参加的是什么比赛

美赛（MCM/ICM）实际上是**两个并列的比赛**，共六道题。它们的评委期望和写作风格有本质差异：

| 维度 | MCM（A/B/C 题） | ICM（D/E/F 题） |
|------|----------------|-----------------|
| 全称 | Mathematical Contest in Modeling | Interdisciplinary Contest in Modeling |
| 核心关注 | 数学模型的**建立与求解** | 跨学科**系统分析**与**方案论证** |
| 评委期待 | 模型严谨、推导完整、求解有效 | 框架完整、讨论深入、建议可行 |
| 典型产出 | 数值结果 + 误差分析 | 系统框架 + 政策建议 + 情景分析 |
| 结论风格 | 学术总结导向 | 政策/方案建议导向 |
| 模型建立比重 | 35-45% | 30-35% |
| 讨论部分比重 | 5-10% | 10-15% |

**一句话区分**：
- MCM 的评委更在意"你怎么算的"——模型本身的正确性和精巧度
- ICM 的评委更在意"你算完之后怎么办"——结论的实际意义和可操作性

这不是说 MCM 不需要讨论、ICM 不需要严谨建模，而是**重心不同**。选 MCM 意味着你要在建模深度上拉开差距；选 ICM 意味着你要在框架完整性和论证说服力上胜出。

## 1.2 论文的本质：不是在"写答案"，而是在"说服评委"

很多新生以为数模论文就是"把解题过程写出来"。这是一种误解。

评委读你的论文时，心里始终在问三个问题：

1. **他们真的理解这个问题吗？**（看问题分析、假设）
2. **他们的方案能解决这个问题吗？**（看模型建立、求解）
3. **他们的结论可靠吗？**（看结果验证、敏感性分析）

整篇论文就是围绕这三个问题，构建一条完整的**论证链**：

```
问题理解 → 简化假设 → 模型设计 → 模型求解 → 结果验证 → 价值判断
```

论文不是在写"我做了什么"，而是在说服评委"我做的东西是对的、有用的、经得起推敲的"。写每一段之前，先问自己：**这一段在回答评委的哪个疑问？**

## 1.3 读者意识：评委是你的"想象中的对话者"

写作时想象一个具体的评委形象：

- 他是数学/工程/科学领域的专家，但**不一定是你这道题具体方向的专家**
- 他在 10-15 分钟内要读完你的论文并给出评分
- 他手里有打分表，在寻找扣分点和加分点
- 如果某个地方他看不懂，他不会查资料——他直接扣分

这意味着：

- **术语第一次出现时必须解释**（即使你觉得是常识）
- **关键结论要突出**（不要藏在段落中间让评委自己找）
- **图表要有标注和说明**（评委不会自己解读一张裸图）
- **结构要清晰可预测**（评委知道每个章节应该在什么位置）

## 1.4 全文结构速览

标准的 7+1 板块结构（100% 的 O 奖论文都有这些板块）：

| 顺序 | 板块 | 推荐页数 | 核心功能 |
|------|------|----------|----------|
| — | **Summary Sheet** | 1 页（单独页） | 让评委在 90 秒内判断你的论文值不值得细读 |
| 1 | Introduction | 2-3 页 | 让评委快速理解问题和你的工作 |
| 2 | Assumptions + Notation | 1-2 页 | 建立建模的基础语言和边界 |
| 3 | Model Establishment | 5-8 页 | 论文心脏——展示你的建模能力 |
| 4 | Results / Application | 4-6 页 | 把模型用到具体问题上，呈现数值结果 |
| 5 | Sensitivity Analysis | 2-3 页 | 证明模型在参数扰动下依然稳定 |
| 6 | Strengths and Weaknesses | 1 页 | 批判性思维展示 |
| 7 | Conclusion | 1-2 页 | 收尾升华 |

**核心原则**：Model + Results 两个板块合计应占正文的 50-60%。这是评委最关注的内容。

这个顺序不是随意安排的——它精确对应评委的认知流程：**先理解问题 → 再看你的方法 → 然后验证结果 → 最后评估可靠性**。不要打乱这个顺序。

# 第二部分：Summary Sheet — 最重要的一页

## 2.1 核心认知：Summary Sheet 不是传统意义上的"摘要"

MCM/ICM 的 Summary Sheet 是**一张独立的页面**，放在论文最前面。它不是期刊论文那种 200 词的抽象摘要，而是一个**压缩版的全论文**——评委经常先读它，如果 Summary Sheet 没打动他，后面的正文可能都不会细看。

标题通常写 `Summary` 或 `Summary Sheet`，也有写 `Abstract` 的，但功能和篇幅是相同的。

## 2.2 长度：真实 O 奖论文的 Summary 有多长？

**真实情况**：O 奖论文的 Summary Sheet **填满整整一页**，通常 300-450 词，密集而全面。

8 句模板是一个**有用的写作框架**（见下文），但不是铁律——真实的 O 奖 Summary 往往更长、更密、包含更多细节。

**核心原则**：不是数词数，而是看你是否在一页内把"问题→方法→结果→价值"说清楚了。如果 Reviewer 读完你的 Summary Sheet 就能复述出你的主要工作，那就是合格的。

## 2.3 结构框架：8 板块模板（教学工具，非强制规则）

以下 8 板块模板是经过大量论文验证的结构骨架，可以作为写作起点。注意：每个板块可以对应 1-3 句话，不必严格 8 句。

| 板块 | 功能 | 典型内容 | 参考词数 |
|------|------|----------|----------|
| 1. 问题/背景 | 让评委知道你在解决什么 | 现实意义 + 具体问题描述 | 30-50 词 |
| 2. 动机/Gap | 说明为什么这个问题值得研究 | 现有方法的不足或问题重要性 | 25-40 词（约 70% 论文包含） |
| 3. 贡献句 | 一句话说清核心工作 | We propose a [模型/框架] that... | 25-40 词 |
| 4. 方法 1 | 展示具体做法 | 核心模型架构/数据处理方法 | 30-50 词 |
| 5. 方法 2 | 展示求解或验证 | 求解方法/模型集成/验证方法 | 30-50 词 |
| 6. 应用场景 | 说明你在什么数据/案例上验证了 | 数据集名称/案例名称 | 20-35 词 |
| 7. 结果（最重要！）| 给出带具体数字的结论 | 百分比、精度、预测值、对比 | 30-60 词 |
| 8. 推广价值 | 说明你的方法不止一个用途 | 适用群体/可扩展场景 | 20-35 词 |

## 2.4 各板块详解

### 板块 1：问题/背景

**功能**：让评委快速进入情境。问题必须具体——不是泛泛的"水资源问题"，而是"预测未来 50 年语言灭绝的规模和地点"。

**模板**：
```
In this paper, we address the problem of [具体问题].
```
**变体**（加入现实意义）：
```
[现实场景] has become a major challenge, leading to [负面影响].
We address the problem of [具体问题].
```
**反面教材**：
```
This paper is about a model for X.  ← 太泛，没有具体问题
```

### 板块 2：动机/Gap（可选）

如果问题本身的重要性已经不言自明（如气候变化、全球健康危机），可以省略。否则，用 1 句说明现有方法的局限。

**常用句式**：
```
Understanding [topic] is critical for [stakeholders].
Previous approaches often overlook [factor], leading to [limitation].
```

### 板块 3：贡献句（最关键的一句）

**功能**：一句话说清你的核心工作。评委接下来会带着这句话去正文里找对应的内容。

**模板**：
```
We propose a [model/framework] that combines [元素A] and [元素B] to [目标].
```

**优秀样本**（2018 C 题）：
```
We propose a data-driven framework that integrates statistical analysis,
machine learning, and optimization techniques to analyze energy profiles
and forecast future consumption.
```

### 板块 4-5：方法详解

第 4 板块通常是核心模型架构或数据预处理；第 5 板块通常是模型求解或集成验证。两者形成"先建模，再求解/验证"的逻辑递进。

**优秀样本**：
```
Specifically, we first develop a clustering-based method to identify
typical daily energy consumption patterns from smart meter data.
Then, we build a prediction model using long short-term memory (LSTM)
networks to forecast hourly energy consumption up to 24 hours ahead.
```

### 板块 6：应用场景

说明你在什么具体场景/数据集上验证了方法。

**模板**：
```
We validate our approach using [数据集/案例来源于何].
```

### 板块 7：结果（最重要）

**这是评委最关心的内容。** 没有具体数字的 Summary 等于承认"我们没有测量过效果"。

**必须包含**：
- 具体数字（百分比、准确率、误差下降量、预测值）
- 与 baseline 的对比（如果题目有隐含 baseline）
- 或者对问题有直接意义的量化结论

**优秀样本**：
```
Our results show that the proposed LSTM model achieves 15% lower
prediction error compared with traditional methods, and the evaluation
framework can identify rate designs that reduce electricity costs by
20% while maintaining grid stability.
```
**反面教材**：
```
Our results show that the model performs well.  ← "好"是多少？
```

### 板块 8：推广/应用价值

说明你的方法不只适用于这一个案例。

**模板**：
```
The proposed framework can be applied by [用户群体] to [用途].
```

## 2.5 各题型 Summary 内容侧重点

8 板块结构在 A-F 题中通用，但内容侧重不同：

| 题型 | 方法描述重点 | 结果类型 | 注意事项 |
|------|-------------|----------|----------|
| A（连续/优化） | 微分方程、优化模型的构建过程 | 数值优化结果、误差分析 | 强调参数标定和模型精度 |
| B（离散/运筹） | 图论、排队论、离散优化的应用 | 路径/配置优化结果 | 强调约束条件的设计 |
| C（数据/统计） | 机器学习流程、特征工程 | 预测精度、分类准确率 | 强调数据处理和模型对比 |
| D（网络/工程） | 网络流、离散事件仿真 | 系统性能指标 | 强调系统框架的完整性 |
| E（环境/政策） | 多准则决策、风险评估体系 | 脆弱性指数、成本估算 | 必须有量化结果，不能只有定性讨论 |
| F（政策/经济） | 博弈论、计量经济学模型 | 均衡结果、政策效果 | 必须有数值，不能只说"我们分析了" |

**重要提醒**：ICM 题（E/F）同样需要量化结果。不要因为是政策题就只给文字分析。O 奖的 E/F 论文都有具体的数值产出。

## 2.6 三套题型大类模板

### 模板 1：优化/连续模型类（A 题常见）

```
In this paper, we address the problem of [具体问题描述].
[背景重要性 or 现有方法 gap].
We propose a [模型名称] model that [核心方法描述].
Specifically, we first [方法1] to [目的1].
Then, we [方法2] to [目的2].
We apply our model to [具体场景], and our results show that [具体数值结果],
[与 baseline 对比 if applicable].
The proposed model can be applied to [推广场景].
```

### 模板 2：数据/机器学习类（C 题常见）

```
In this paper, we address the problem of [预测/分类/分析问题].
With the increasing adoption of [技术背景], understanding [问题]
has become essential for [利益相关方].
We propose a [框架名称] that integrates [技术A], [技术B], and [技术C] to [目标].
Specifically, we first [数据处理方法] to [目的1].
Then, we [模型方法] to [目的2].
We validate our approach using [数据集], and our results show that [具体数值结果].
The proposed framework can be applied by [用户群体] to [用途].
```

### 模板 3：政策/评估类（D/E/F 题常见）

```
In this paper, we address the challenge of [评估/规划/设计问题].
The transition to [背景] offers significant opportunities for [价值],
but also poses [挑战].
We propose an integrated framework that optimizes [目标] while
considering [约束/不确定性].
Specifically, we first develop [模型/方法A] to [目的1].
Then, we incorporate [模型/方法B] to [目的2].
We apply our framework to [案例], and our results show that [具体数值结果].
We also identify [key findings].
The proposed framework can be used by [用户群体] to [用途].
```

## 2.7 Summary Sheet 检查清单

- [ ] 问题是否具体？（不是泛泛的"水资源问题"）
- [ ] 贡献句是否说清了模型/框架的核心组成？
- [ ] 方法描述是否具体可操作？（读完能复述你做了什么）
- [ ] **是否有具体数字？**（这是及格线）
- [ ] 是否填满了一页？
- [ ] 没有 "See Figure X"（Summary 里不引用图表）
- [ ] 没有 "The results are good/bad"（空话）
- [ ] 没有 "Further research is needed"（留着结论写）
- [ ] 没有大段复制赛题文字
- [ ] 缩写第一次出现有全称
- [ ] 术语有适当解释

# 第三部分：Introduction（引言）

## 3.1 功能与篇幅

**功能**：让评委在 2 分钟内搞懂三个问题——赛题在问什么、你做了什么、你怎么做的。

**推荐页数**：2-3 页。此前的文件中"1-2 页"对初学者偏紧（O 奖论文通常需要展开背景和问题分析），"3-4 页"又偏多（过多展开会挤占核心建模篇幅）。2-3 页是一个合适的平衡。

## 3.2 标准三段式结构

```
1.1 Background（背景，1-2 段）
    - 这个问题的现实意义是什么
    - 为什么这个问题重要（可以引用现实数据或事件）
    - 注意：第一段通常一句话开门见山，不要写成科普文章

1.2 Restatement of the Problem（问题重述，1-2 段）
    - 用你自己的语言复述赛题要求
    - 明确列出你要解决哪些具体子问题（numbered list）
    - 可以将赛题语言"翻译"成数学建模的任务描述

1.3 Our Work / Overview（本文工作，1-2 段）
    - 简要说明你建立了什么模型、用什么方法求解
    - 可以给一个流程图或 roadmap，让评委知道后面会看到什么
```

## 3.3 写作要点

1. **问题重述不要抄原题**。赛题原文评委比你熟。你需要做的是"翻译"——把赛题描述转化为建模任务。例如：
   - 赛题说"分析影响浴缸水温的因素" →
   - 你写"我们建立热传导模型，量化水深、时间、初始温度对水温下降速率的影响"

2. **引言的篇幅控制**：如果 Introduction 超过 3 页，说明你可能在写文献综述——精简背景，把篇幅留给建模。

3. **Roadmap 要具体**。不要只说"接下来我们将建立模型"。要说"我们首先建立热传导模型（Section 3），然后用 Runge-Kutta 方法求解（Section 4），最后对关键参数做敏感性分析（Section 5）"。

4. **第一段要抓人**。一句有力的事实陈述比五句泛泛而谈更有效。

**反面教材**：把赛题原文复制粘贴当"问题重述"——这是评委最清楚也最讨厌的写法。

# 第四部分：Assumptions and Notations（假设与符号）

## 4.1 核心认知：假设是在"购买"简化权

很多新生以为假设只是走过场的形式。实际上，**假设是你向评委解释"我做了什么简化、为什么可以这样简化"的地方**——这是评委判断你"是否真的理解模型局限性"的关键位置。

评委看假设时心里在问：
- 这个团队理解模型的适用边界吗？
- 他们的简化是合理的，还是过度的？
- 这些简化对结果有什么影响？

**好的假设 = 必要的简化 + 充分的理由**。没有理由的假设等于承认"我们拍脑袋，无法自圆其说"。

## 4.2 假设的组织方式：三种模式

| 模式 | 描述 | 出现频率 | 适用场景 |
|------|------|----------|----------|
| 模式 A（推荐） | 独立章节 "Assumptions and Justifications" | ~60% | 假设数量 5-8 条 |
| 模式 B | 与 Notation 合并为 "Model Preparation" | ~35% | 假设较少，或需要精简结构 |
| 模式 C | 假设嵌入各子模型内部 | ~5% | 仅当子模型间假设差异极大时 |

**推荐模式 A**。独立成节便于评委查阅，结构更专业。假设章节通常紧跟在 Introduction 之后（第 2 或第 3 章）。

## 4.3 Justification 的五种内容类型

### 类型 1：简化合理性（最常见）

说明假设如何简化复杂现象，同时保持足够精度。

```
Assumption: We assume the water temperature in the bathtub is uniform.
Justification: The water volume is small (approximately 200L) and
natural convection ensures sufficient mixing. This simplification
reduces the PDE to an ODE without significant loss of accuracy.
```
**句式特征**：because / since 引导原因

### 类型 2：数据/标准引用

引用权威来源支撑假设参数。

```
Assumption: Transmission losses are 6% of total electricity generated.
Justification: According to U.S. EIA data, average transmission and
distribution losses for U.S. utilities range from 4% to 7%. We adopt
6% as a reasonable midpoint for our analysis.
```
**句式特征**：According to... / Based on... data

### 类型 3：文献/框架引用（E 题等政策类常见）

引用学术框架建立理论依据。

```
Justification: Based on the IPCC framework for climate risk assessment,
these three dimensions capture the primary characteristics of climate
hazards affecting infrastructure systems.
```

### 类型 4：参数估计说明

说明为什么用某个估计值而非其他值。

```
Justification: Sedimentation rates in similar dam systems show consistent
patterns with the selected empirical formula, validated by multiple
field studies.
```

### 类型 5：时效性/适用期说明

针对"模型有效期"的假设。

```
Assumption: The adaptive capacity of communities remains constant
within the 10-year modeling period.
Justification: While adaptive capacity changes over decades, for a
10-year projection, treating it as constant does not significantly
affect conclusions.
```

## 4.4 Justification 深度：写几句话？

| 深度 | 长度 | 适用场景 |
|------|------|----------|
| 简洁 | 1 句 | 假设本身已自说明（"时间是非负的"）或参数来源明确 |
| 标准 | 2-3 句 | 多数假设——先说原因，再说简化效果 |
| 详细 | 3-5 句 | 复杂假设（涉及 IPCC 框架、多方制约因素等） |

## 4.5 假设数量

**推荐 5-8 条**。这是绝大多数 O 奖论文的范围。

| 数量 | 评价 |
|------|------|
| 3-4 条 | 偏少，简单问题可接受 |
| 5-8 条 | **推荐** |
| 10+ 条 | 可接受但要避免"凑数"感 |

**关键原则**：
1. 每条假设**必须被后文实际使用**——写了但没用的假设是浪费篇幅，也会让评委觉得你不清楚自己在做什么
2. 核心假设（影响结果最大的）要有详细 justification
3. 假设之间不能相互矛盾

## 4.6 假设章节模板

```
2 Assumptions and Justifications

Assumption 1: [一句话描述假设]
Justification: [2-3 句，说明为什么这个假设是合理的，可引用
数据/文献/标准/逻辑推理]

Assumption 2: [同上]
Justification: [同上]

Assumption 3: [参数估计类假设]
Justification: Based on [数据来源/文献], we adopt [具体数值]
as a reasonable estimate. This value falls within the typical range
of [范围], and our sensitivity analysis (Section X) confirms that
small variations do not significantly affect our conclusions.
```

## 4.7 符号说明（Notation）

### 要不要单独成节？

**强烈推荐单独成节**。独立出现频率约 40-60%。好处：
1. 评委不需要在建模过程中来回翻找符号定义
2. 显得专业，条理清晰
3. 字数少但作用大——性价比极高

### 位置

通常在 Assumptions 之后。两种常见组织方式：

| 方式 | 出现频率 |
|------|----------|
| 假设独立 + 符号独立（两个章节） | ~40% |
| 合并为 "Assumptions and Notation"（一个章节） | ~45% |
| 符号随文定义（嵌入式） | ~15%（不推荐）|

### 写法规范

```
Table 1: Notations

Symbol    Description                    Unit
--------  -----------------------------  ----
x         position along the bathtub     m
T         water temperature              °C
t         time                           s
...
```

**注意事项**：
- 按字母顺序或出现顺序排列（全文保持一致即可）
- 只列出**正文实际使用的符号**，不要堆砌
- 常见符号（t 表示时间）不需要解释
- 单位要标注

## 4.8 假设与符号常见错误

1. 假设没有理由——评委内心："凭什么？"
2. 理由是循环论证——"We assume X is constant for simplicity." ← 这不是理由
3. 假设在后文中从未出现——写了但没用的假假设
4. 假设之间相互矛盾——前文说 A 成立，后文隐含非 A
5. 符号定义表过分膨胀——包含了 50+ 个符号，实际只用了 15 个

# 第五部分：Model Establishment（模型建立）

## 5.1 核心定位

模型建立是**论文的心脏**，占总页数的 30-40%。你的核心工作都在这里。评委在这个章节里找两个东西：**你用了什么方法？为什么用这个方法？**

## 5.2 模型章节的组织方式

### 模式 1：按模型类型分节（推荐，~60% 论文采用）

```
3 Model Establishment

3.1 The [Name] Model
    3.1.1 Model Formulation（数学公式推导）
    3.1.2 Parameter Estimation（参数来源和估计方法）

3.2 The [Name] Model
    3.2.1 Model Formulation
    3.2.2 Parameter Estimation

3.3 Model Integration（可选）
```

**优点**：结构清晰，评委可以快速定位每个模型。
**适用**：题目有多个子问题，每个需要不同模型。

### 模式 2：按问题流程分节（~25%）

```
3 Model Establishment

3.1 Data Preprocessing [1-2 页]
3.2 Core Model [3-4 页]
3.3 Model Integration [1-2 页]
```

**适用**：方法有明显的流水线（数据→特征→模型→输出），C 题常用。

### 模式 3：单模型深入（~15%）

```
3 The [Name] Model

3.1 Model Formulation [3-4 页]
3.2 Solution Method [2-3 页]
3.3 Model Validation [1 页]
```

**适用**：问题高度聚焦，A 题常用。

## 5.3 写法要点

1. **先给模型起名字**（如 "The Heat Transfer Model"），再展开公式。名字让读者有一个"锚点"。
2. **每层子节都要有明确目的**。不要堆砌公式——每展示一个公式，前后都要有文字解释它在做什么。
3. **公式中每个符号都要清楚定义**。不要让评委自己去猜某个变量的含义。
4. **如果是已有模型**（如 Logistic 回归、SIR 模型），要说明**为什么这个模型适合你的场景**——这不是在显示你"知道"这个模型，而是在显示你"理解"何时用它。
5. **如果是改进或创新模型**，要明确指出**改进点在哪里**，与原模型有什么区别。

## 5.4 模型章节内部篇幅分配（以 6 页为例）

| 子节 | 推荐篇幅 | 内容 |
|------|----------|------|
| 模型 1（核心模型） | 2-3 页 | 公式推导 + 参数估计 |
| 模型 2（第二核心） | 2-3 页 | 公式推导 + 参数估计 |
| 模型 3（辅助/验证） | 1-2 页 | 简要说明 |
| 模型集成（如有） | 0.5-1 页 | 多模型协同关系 |

---

# 第六部分：Results / Model Application（结果与应用）

## 6.1 功能

用你的模型解决赛题的具体问题，把数值结果呈现出来。这是展示"你的模型到底能不能用"的地方。

## 6.2 组织模式

| 模式 | 结构 | 适用 |
|------|------|------|
| 模式 1（推荐） | Results 单独成章，集中展示所有数值结果 | 结果数量多，需要系统展示 |
| 模式 2 | 每个模型后直接跟 Application | 模型与结果对应紧密 |

## 6.3 标准结构

```
4 Results and Discussion

4.1 Application to [Sub-problem 1]
    [图/表 + 1-2 段分析]

4.2 Application to [Sub-problem 2]
    [图/表 + 1-2 段分析]

4.3 Application to [Sub-problem 3]（如有）
    [图/表 + 1-2 段分析]

4.4 Comparison with Baseline Methods（推荐）
    [对比图表 + 分析]
```

## 6.4 结果展示规范

1. **每张图/表要有标题和编号**（如 "Figure 3: Temperature decay over time"）
2. **图下方要有一句话总结关键发现**——不要让评委自己从数据里找结论
3. **关键数值结果加粗**或用其他视觉方式突出
4. **要有误差分析**——如果有误差或不确定性，说明来源
5. **先给数值结果，再分析原因**——不要倒过来

---

# 第七部分：Sensitivity Analysis（敏感性分析）

## 7.1 功能

证明你的模型在参数扰动下依然稳定。这是 O 奖论文中出现率最高的章节之一（接近 100%），也是评委判断模型"是否真的有效"的关键。

**评委在这个章节里看**：你的模型是脆弱的（参数稍微一变结论就不同了）还是稳健的？

## 7.2 标准结构

选择 **3-5 个关键参数**进行敏感性分析——不是每个参数都做（那叫枚举，不叫分析）。

```
5 Sensitivity Analysis

5.1 Parameter [X]（敏感性分析对象）
    [改变参数 X ±10%、±20% 等，观察结果如何变化]
    [用图表展示结果变化]
    [分析为什么这个参数敏感/不敏感]

5.2 Parameter [Y]
    [同上]

5.3 Parameter [Z]
    [同上]

5.4 Summary（综合讨论）
    [哪些参数敏感，哪些稳健，有什么实际意义]
```

## 7.3 篇幅分配

| 内容 | 推荐页数 |
|------|----------|
| 参数 X 的敏感性分析 | 0.5-1 页 |
| 参数 Y 的敏感性分析 | 0.5-1 页 |
| 参数 Z 的敏感性分析 | 0.5-1 页 |
| 综合讨论 | 0.5 页 |

## 7.4 写法要点

1. 选择**对结果影响最大的参数**分析，不要面面俱到
2. **必须用图表**（折线图、热力图、柱状图），纯文字说明不够直观
3. 最后总结哪些参数敏感、哪些稳健
4. 如果某些参数过于敏感，要讨论**现实意义**——这在实际中意味着什么？

**反面教材**：
- 只做一个参数的敏感性分析（太少）
- 不绘图，只给文字描述（不够直观）
- 敏感性分析的结论与前文矛盾（说明模型内部不自洽）

# 第八部分：Strengths and Weaknesses（优缺点讨论）

## 8.1 功能

展示批判性思维，主动承认模型的局限。**这是成熟论文的标志。** 主动承认缺点比被评委发现缺点要好——这会让评委觉得你这个团队有自知之明，懂得模型的边界。

## 8.2 写法规范

```
6 Strengths and Weaknesses

6.1 Strengths
    - [优点 1]：具体说明是什么优点，为什么有价值，不要空泛
    - [优点 2]：同上
    - [优点 3]：同上

6.2 Weaknesses
    - [缺点 1]：具体说明什么缺点，承认它，说明你采取了什么缓解措施
    - [缺点 2]：同上
    Future Work 可以在此提及（1-2 句）
```

## 8.3 写作要点

- **优点要具体**。不要 "our model is good"——要说 "our model captures the nonlinear coupling between temperature and humidity, which single-variable models cannot"
- **缺点要诚实**，但也要说明你采取了什么措施缓解（"we conducted sensitivity analysis to bound the impact of this assumption"）
- **缺点 2-3 条足够**，写多了显得模型不可靠
- 可以写 Future Work 作为缺点的补充方向

---

# 第九部分：Conclusion（结论）

## 9.1 功能

收尾，强调你的主要贡献。不要重复前文，要做**升华**——从前文的具体结论中提炼出更一般性的发现。

## 9.2 写法要点

1. 总结主要工作（1-2 句，简洁）
2. 强调核心结果和贡献（1-2 句，数字 + 意义）
3. 如果有实际应用价值，点出来
4. **不要写 "Further research is needed"**——这是废话，Strengths and Weaknesses 已经讨论过局限了

**MCM vs ICM 结论风格差异**：
- MCM（A/B/C 题）：结论偏学术总结——"我们的模型成功解决了什么问题，精度达到多少"
- ICM（D/E/F 题）：结论偏政策建议——"基于我们的发现，我们建议决策者采取什么措施"（F/E 题尤其如此）

---

# 第十部分：A-F 题写作侧重点与 MCM vs ICM 差异

> 这是本指南最核心的差异分析章节。此前的文件将跨题型差异散落在多个文件中，本文将全部整合并修正。

## 10.1 核心结论：结构高度一致，差异在于内容深度与侧重点

**所有题型都包含相同的 7 个标准章节**（Introduction, Assumptions, Model, Results, Sensitivity Analysis, Strengths/Weaknesses, Conclusion）。题型不改变结构，只改变你**在哪些章节花更多篇幅、写什么类型的内容**。

**唯一的结构差异**：C/D/E/F 题比 A/B 题更倾向于有独立的 Data 章节（~80% vs ~50%）。数据驱动型题目需要专门展示数据处理过程。

## 10.2 MCM（A/B/C 题）整体写作特征

```
重心底座：
├── Model Development（35-45%）← 模型是绝对核心
├── Results（15-20%）
├── Introduction（10-15%）
└── Sensitivity Analysis（5-10%）
```

**特点**：
- 模型建立是绝对重心——评委最关心"你怎么建模的"
- 结果展示相对简洁直接
- Discussion 部分较弱或并入 Results
- 结论偏学术总结风格

**核心写作理念**：**让模型说话**——把模型的数学结构、求解方法和精度作为论文最亮的点。

## 10.3 ICM（D/E/F 题）整体写作特征

```
重心底座：
├── Model Development（30-35%）← 模型仍是核心，但比例略降
├── Results + Discussion（20-25%）← 讨论比 MCM 厚重得多
├── Policy Implications（10-15%）← ICM 标志性产出（E/F 题）
├── Introduction（10-12%）
└── Sensitivity Analysis（5-8%）
```

**特点**：
- Discussion 比 MCM 厚重——不仅要展示结果，还要深入解释其实际意义
- Policy/Strategy 推荐是 ICM 的标志性产出
- 结果解释更注重实际意义，而非纯数学精度
- Case Study（多国对比）在 E 题几乎必出现
- 结论偏政策建议导向

**核心写作理念**：**让结论有用**——把模型的现实解释力和政策指导价值作为论文最亮的点。

## 10.4 MCM vs ICM 关键差异对照表

| 维度 | MCM (A/B/C) | ICM (D/E/F) |
|------|-------------|-------------|
| 评审核心关注 | 模型数学严谨性 | 框架完整性和方案可行性 |
| 模型建立比重 | 35-45% | 30-35% |
| Discussion 比重 | 5-10% | 10-15% |
| Policy 章节 | 无 | E 题 ~90%、F 题 ~75% |
| Data 章节 | C 题必有，A/B 题 ~50% | D/E/F 题 ~80% |
| Case Study（多国） | 少有 | E 题 ~90%、F 题 ~50% |
| 公平性/伦理讨论 | 无 | E 题 ~60%、F 题 ~40% |
| Literature Review | 少有 | F 题 ~50% |
| 结论风格 | 学术总结导向 | 政策建议导向 |

## 10.5 各题型分述

### A 题：偏"机理—过程—动态系统"

**近十年主题特征**：hot bath、Zambezi River、ecology、moving north、fungi、cyclist、plant communities、sex ratios、stairs wear——常常涉及生态、物理、生物、连续动态过程。

**核心挑战**：先把"系统怎么运转"想明白，再做简化和建模。

**结构特征**：单一深度模型，剥洋葱式。
```
典型 A 题模型结构：
├── Model I: [核心模型，占 40-50% 篇幅]
│   ├── Model Description
│   ├── Mathematical Formulation（常包含微分方程）
│   ├── Parameter Estimation
│   └── Results
├── Model II: [辅助模型]（如需要）
└── Model III: [验证模型]（如需要）
```

**写作侧重点**：
- **假设的合理性和自洽性**是拉开差距的关键——A 题评委特别关注你是否理解了系统机理
- 模型推导要有物理/生物直觉的支撑，不是纯数学推演
- 参数标定要有依据（实验数据、文献值）
- 微分方程/差分方程的离散化和数值求解方法是必须写清楚的

**近五年方法趋势**：跨学科借鉴（生理学/生态学）+ 微分方程系统 + 参数标定。常见方法包括 Logistic ODE、Lotka-Volterra、ARIMA、Monte Carlo、Runge-Kutta 等。

**一句话建议**：把这个模型做深做透，别浅尝辄止。

---

### B 题：偏"工程—运营—优化与调度"

**近十年主题特征**：space junk、merge after toll、disaster relief drones、wildfires、hydroelectric sharing、submersibles、sustainable tourism——资源分配、路径规划、调度优化、仿真评估。

**核心挑战**：多个子问题需要不同方法组合，找到每种问题的最适配方法。

**结构特征**：多模型并列，服务于不同子问题。
```
典型 B 题模型结构：
├── Model 1: [模型A]（对应 Problem 1）
├── Model 2: [模型B]（对应 Problem 2）
└── Model 3: [模型C]（对应 Problem 3）
```

**写作侧重点**：
- **目标函数和约束条件**的推导和论证——这是优化类论文的命门
- **方案比较**——不只给出一个方案，要比较不同配置的效果
- 执行可行性分析——你的方案在现实中是否可操作？
- 约束条件的设计逻辑要说清楚（为什么取这个上下界？）

**近五年方法趋势**：多方法组合 + 跨学科概念（经济学/生态学）× 优化框架。常见方法包括线性规划、多目标优化、元胞自动机、禁忌搜索、AHP 等。

**一句话建议**：用合适的模型做合适的事，别所有问题用同一个方法硬套。

---

### C 题：偏"数据—预测—评价—应用说明"

**近十年主题特征**：Goodgrant Challenge、cooperate and navigate、energy production、opioid crisis、Wordle、tennis momentum、Olympic medal tables——数据驱动、统计建模、预测评价、应用型分析。

**特殊之处**：美国统计协会单列了 C 题奖项，官方强调看重 usefulness、clarity、creative and effective use of the data。

**核心挑战**：不仅要"算"，更要"把数据讲清楚"——数据处理和解释的重要性不低于模型本身。

**结构特征**：问题导向的流水线——按 Problem 1/2/3/4/5 组织，每问题一模型。
```
典型 C 题结构：
├── Data Description / Data Cleaning（独立章节，~90% 有）
├── Problem 1: [模型A] → 问题分析→模型→求解→结果
├── Problem 2: [模型B]
├── Problem 3: [模型C]
├── Problem 4: [模型D]
├── Problem 5: [模型E]
└── Letter / Memorandum（给决策者的信，~90% 有）
```

**写作侧重点**：
- **Data Cleaning 独立成节**——这是 C 题标配，展示你理解数据的质量、缺失值处理、异常值识别
- **模型对比**——不只给一个模型的结果，要跟至少一个 baseline 比较
- **结果要有统计显著性说明**——p 值、置信区间、交叉验证
- **Letter/Memorandum**——C 题通常有一封给决策者的信，格式为：
  ```
  Dear [决策者],
  [第一段] 问题背景和我们的方法
  [第二段] 核心发现和建议
  [第三段] 具体行动建议
  [落款]
  ```

**近五年方法趋势**：深度学习（2020 后标配）+ 传统统计组合。常见方法包括 CNN、LSTM、GRU、XGBoost、Prophet、随机森林、K-Means 等。

**一句话建议**：按流程一步步解决问题，每步都要有清晰的数据处理逻辑和模型选择理由。

---

### D 题：偏"系统设计—决策支持—跨学科集成"

**近十年主题特征**：信息网络、机场安检、EV 出行、卢浮宫疏散、teaming strategies、music influence、UN SDGs、Great Lakes water——系统级决策问题，多个子模块拼成完整框架。

**核心挑战**：不只是单一模型，而是各个子模型拼到一起能不能形成完整框架。

**结构特征**：三模型固定组合（六种题型中结构最"标准化"）。
```
典型 D 题结构：
├── 1. Introduction
├── 2. Problem Background + Assumptions
├── 3. Data Processing
├── 4. Model Overview（概念模型 + 指标体系）
├── 5. Sub-Model 1: Propagation Model（传播/演化模型）← 微分方程、差分方程
├── 6. Sub-Model 2: Optimization Model（优化模型）← 线性规划、整数规划
├── 7. Sub-Model 3: Game Theory Model（博弈模型）← 纳什均衡
├── 8. Model Application（按 Problem 分节）
├── 9. Sensitivity Analysis
└── 10. Conclusion
```

**三模型功能分工**：

| 子模型 | 功能 | 典型方法 |
|--------|------|----------|
| Propagation Model | 模拟系统演变/扩散/传播 | 微分方程、差分方程、系统动力学 |
| Optimization Model | 求最优决策/配置 | 线性规划、整数规划、多目标优化 |
| Game Theory Model | 分析多方利益冲突 | 博弈论、纳什均衡 |

**写作侧重点**：
- **总框架图**——在 Model Overview 里放一张系统框架图，展示子模型之间的关系
- **各子模型之间的接口**——模型 A 的输出如何变成模型 B 的输入？
- **指标体系**——D 题通常需要定义评估指标
- **网络分析**（PageRank、中心性等）是 D 题持续热点

**一句话建议**：先搭好总框架（概念模型），再填子模型。最怕只有零散模型没有总框架。

---

### E 题：偏"可持续发展—环境—资源政策"

**近十年主题特征**：thirsty planet、sustainable cities、climate instability、plastic、food systems、carbon sequestration、light pollution、property insurance、agriculture——几乎全是 sustainability 线。

**核心挑战**：构建覆盖系统全环节的模型，同时给出有依据的政策建议。

**结构特色**：
```
E 题特有章节：
├── Case Study: [国家A] & [国家B]（多国对比，~90% 出现）
├── Policy Suggestion / Strategy
├── Equity Issues and Solutions（~60% 出现）
└── Scalability Analysis
```

**模型结构特色**：倾向于构建覆盖**系统全环节**的模型。
```
典型 E 题模型结构（以食物系统为例）：
├── Model 1: Food Production Process Model（生产）
├── Model 2: Food Transportation Process Model（运输）
├── Model 3: Food Sale Process Model（销售）
└── Model 4: Sustainability/Evaluation Model（评估）
```

**写作侧重点**：
- **指标体系**——多维度评估（环境 + 经济 + 社会）
- **多国对比**——Case Study 几乎必做，常选发达国家 vs 发展中国家
- **公平性讨论**——方案对弱势群体是否公平？
- **政策建议不是"拍脑袋"**——每条建议都要有模型结果支撑
- **组合赋权**（AHP + 熵权法）是 E 题标配
- 结果分析比"算出一个数"更重要——评委更关心"你的政策建议为什么合理"

**一句话建议**：构建完整系统模型，用多国案例证明你的方法有普适性。

---

### F 题：偏"社会治理—政策—风险—伦理与制度"

**近十年主题特征**：refugee immigration、Mars migration、privacy、digital currency、higher education、space governance、green GDP、illegal wildlife trade、cyber security——制度设计、社会影响、风险评估、伦理治理。

**核心挑战**：把"定量模型 + 情景分析 + 政策讨论"绑在一起，三者缺一不可。

**结构特征**：
```
F 题特有元素：
├── Policy Implications（~75% 独立成节）
├── Ethical Analysis（~40% 建议有）
├── Literature Review（~50% 独立成节）
├── Discussion（10-15%，比 MCM 厚重）
└── 博弈模型（~60% 出现）
```

**写作侧重点**：
- **Policy Implications 是标志性产出**——没有政策建议的 F 题论文是残缺的
- **博弈模型**（寡头博弈、Super-game、囚徒困境）是常用框架
- **公平性测度**（Theil 指数、Shapley 值）经常出现
- **伦理分析**——方案对社会不同群体有什么影响？
- **情景分析**——不同政策选择导致的长期后果
- Discussion 厚重（10-15%）——比 MCM 题讨论多得多

**F 题 vs D 题对比**：

| 维度 | F 题 | D 题 |
|------|------|------|
| 核心模型 | 评价 + 博弈 | Propagation + Optimization + Game |
| Policy 章节 | ~75% 独立成节 | <10% |
| 结果讨论 | 厚重（10-15%）| 适中（5-10%）|
| 结论风格 | **政策建议导向** | 学术总结导向 |
| 敏感性分析 | 比重较低（5-8%）| 适中（5-10%）|

**一句话建议**：定量模型打底，政策讨论点睛——数据和论证让你的政策建议不是空谈。

# 第十一部分：方法论与创新策略

> 基于 2020-2024 年 A/B/C/D/E/F 六道题 O 奖论文分析，每题每年约 3 篇，共约 90 篇样本。

## 11.1 核心结论：方法 ≠ 获奖决定因素

> O 奖论文的亮点从来不在于用了什么"高大上"的模型名称，而在于：**如何将一个问题拆解成可解决的组件，如何选择/改进方法去适配具体问题。**

根据对近五年 O 奖论文的分析，方法来源大致分为三个层次：

- **课程常见方法（~80%）**：如回归分析、AHP、多目标优化、K-means——几乎所有参赛者都学过，但 O 奖论文的用法往往有针对性改进
- **跨学科借鉴（~15%）**：如从经济学引入拍卖理论、从生态学引入 Lotka-Volterra 竞争模型——核心创新在于"把一个学科的概念迁移到另一个领域"
- **自创/改进方法（~5%）**：如 CE-VADER、X-Prophet、GSRF——通常是现有方法的组合改进

**真正的区分点**：方法是否适配问题——评委不会因为你的方法"高级"而给高分，但会因为方法"不适合"而扣分。

## 11.4 创新来源四分类

### 来源 1：跨学科借鉴（可操作性高）

从其他学科找"这个问题从来没被这样想过"的灵感：

| 来源学科 | 可引入概念 | 适配问题类型 |
|----------|-----------|-------------|
| 经济学 | 边际效用、机会成本、拍卖理论 | 资源分配、竞争问题 |
| 生态学 | Lotka-Volterra、种间竞争、演替模型 | 生物、环境、政策评估 |
| 物理学 | 扩散方程、势函数、热传导 | 空间传播、污染扩散 |
| 运动生理学 | 功率曲线、三阶段模型 | 骑行、策略优化 |
| 社会学 | 基尼系数、均衡理论 | 公平性分析、政策评估 |

### 来源 2：方法组合创新（可操作性高）

不发明新方法，而是创造性地组合现有方法：

- AHP（主观赋权）+ 熵权法（客观赋权）= **综合赋权**
- 熵权法 + TOPSIS = **综合评价决策**
- 多目标优化 + 泊松约束 = **考虑极端事件的优化**
- 回归预测 + 随机残差 = **考虑个体异质性**
- 网络中心性 + 综合评价 = **多维度排序**

### 来源 3：场景适配创新

把一个领域的方法迁移到完全不同的场景——这是 O 奖论文中最有想象力的创新类型：

| 典型案例 | 原方法应用场景 | 迁移到的新场景 |
|----------|---------------|---------------|
| 拍卖理论 → 水资源分配 | 经济学拍卖 | 2022B 多州竞争 |
| Lotka-Volterra → 文化保护 | 生态学生物竞争 | 2020F 文化传播分析 |
| SIRS 模型 → Wordle 传播 | 流行病学 | 2023C 游戏传播分析 |
| 功率曲线 → 骑行策略 | 运动生理学 | 2022A 自行车赛优化 |
| ALARP → 光污染风险 | 工业安全 | 2023E 环境评估 |

### 来源 4：指标定义创新

**把单一指标拆成多维度，每个维度用不同方法计算，再加权合成**。这是"几乎不涉及新数学，但看起来很有深度"的创新策略。

经典案例：
- 损伤指数：多个损坏因素合并为单一指标
- PII 指数：环境-经济-社会三维 policy 驱动评估
- 香槟塔模型：按优先级逐层分配资源
- 继承度：音乐特征传染性量化

## 11.5 五种赛场快速创新策略

### 策略 1：组合现有方法

不要用单个方法，用 2-3 个方法的组合 + 合理的权重设计。

**常见有效组合**：
- 熵权法（客观）+ AHP（主观）= 综合赋权
- TOPSIS + K-means = 先分类再排序
- 回归 + 随机残差 = 考虑异质性
- 多目标优化 + 概率分布 = 考虑随机性

### 策略 2：跨学科概念引入

从其他学科借概念，创造"这个问题从来没被这样想过"的新视角：

| 学科 | 快速可引入概念 | 适配场景 |
|------|---------------|---------|
| 经济学 | 边际效用、机会成本 | 资源分配、效益评估 |
| 生态学 | 种间竞争、Logistic 增长 | 生物种群、政策效果 |
| 物理学 | 扩散方程、势函数 | 污染传播、信息扩散 |
| 博弈论 | 囚徒困境、纳什均衡 | 多方利益冲突 |

### 策略 3：自创评分体系

把单一指标拆成多维度，设计维度间权重：

1. 识别问题的多个利益方/维度
2. 为每个维度选择合适的评估方法
3. 设计维度间权重（AHP 或客观赋权）
4. 定义最终综合评分公式

### 策略 4：空间化/网络化处理

把静态评价改成"每个位置有值，且受邻居影响"：

- 用卷积核描述空间传播（热传导、污染扩散）
- 用图/网络描述节点间关系（PageRank）
- 用距离衰减函数描述影响力衰减
- 用多层网络描述不同层面的关系

### 策略 5：时间维度扩展

从"当前最优"变成"跨时序最优"：

- 加入预测模型（ARIMA、灰色预测）
- 用泊松/马尔可夫描述随机事件
- 用时间序列描述演化趋势
- 加入贴现率/时间价值

---

## 11.6 评分标准与评委视角

评委判断论文质量的四个核心维度：

1. **问题理解深度**——能不能抓住问题的核心矛盾
2. **方法选择依据**——为什么这个方法适合这个问题（而非"我会这个方法所以用了"）
3. **模型创新程度**——是否只是套用模板，还是针对问题做了有针对性的适配
4. **结果验证完整性**——敏感性分析、鲁棒性检验、误差分析

**关键认知**：创新程度不取决于方法是否"高级"，而取决于方法是否**针对问题特点做了适配**。

---

## 11.7 方法论核心要点总结

1. **O 奖论文的方法 80% 在课程范围内，但组合方式高度创新**
2. **真正的创新点在于：问题理解 → 方法选择 → 适配改进的过程**
3. **快速小创新的核心：跨学科借鉴 + 多方法组合 + 场景化适配**
4. **不要追求"这个方法我没学过"，要追求"这个方法为什么适合这个问题"**

# 第十二部分：常见问题与综合检查清单

## 12.1 页数不够怎么办？

**不要为了填页数而注水**。更有效的方法：

1. 增加敏感性分析的深度（多做 1-2 个参数）
2. 增加结果分析的解读（每张图配更深入的分析讨论）
3. 补充 baseline 对比（与文献中的已有方法比较）
4. 适当扩展文献综述（如果 Introduction 薄弱）

## 12.2 页数太多怎么办？

**先删什么**（按优先级）：

1. 过多的文献综述（Introduction 中 2-3 段足够）
2. 重复的结果展示（一张图能说清的不用两张）
3. 过于详细的参数来源说明（可移至附录）
4. 过长的 Assumptions（每条假设 1 段足够）
5. 附录中的代码（代码不是评委关注点）

## 12.3 Summary Sheet 检查清单

- [ ] 问题是否具体？
- [ ] 贡献句是否说清了模型/框架的核心？
- [ ] 方法描述是否具体可操作？
- [ ] **是否有具体数字？**（及格线）
- [ ] 是否填满了一页？
- [ ] 没有 "See Figure X"
- [ ] 没有 "The results are good/bad"
- [ ] 没有 "Further research is needed"
- [ ] 没有大段抄赛题
- [ ] 缩写第一次出现有全称

## 12.4 假设章节检查清单

- [ ] 每条假设都有 Justification
- [ ] Justification 长度与假设复杂度匹配
- [ ] 假设在后文被实际使用
- [ ] 没有假设之间的相互矛盾
- [ ] 数量在 5-8 条之间
